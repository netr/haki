      <Back><div>A metric used to evaluate the performance of ranking algorithms, particularly in information retrieval, search engines, and recommendation systems.</div><h3><strong>Key Concepts</strong>:</h3><ol><li><div><strong>Purpose</strong>:</div><ul><li>Measures the quality of the ranking produced by an algorithm relative to an ideal ranking.</li><li>Accounts for both the relevance of results and their order in the list.</li></ul></li><li><div><strong>Discounting</strong>:</div><ul><li>Assigns higher importance to relevant items appearing earlier in the ranking.</li><li>Uses a logarithmic scale to reduce the impact of lower-ranked items.</li></ul></li><li><div><strong>Normalization</strong>:</div><ul><li>Ensures that scores are comparable across queries by dividing the raw DCG by the ideal DCG (i.e., the best possible ranking).</li><li>Produces a value between 0 and 1, where 1 represents a perfect ranking.</li></ul></li></ol></Back>

      <Front>How does 'Data Federation' differ from traditional data warehousing?</Front>
      <Back><div><strong>Data Federation</strong> is a data management approach that allows an application to retrieve, integrate, and manipulate data from multiple distributed sources in real-time, without the need to physically store or move the data.</div><div><h3><b>Key Differences in Table Form:</b></h3><table><tbody><tr><th>Aspect</th><th>Data Federation</th><th>Traditional Data Warehousing</th></tr><tr><td><strong>Data Location</strong></td><td>Data remains in original source systems.</td><td>Data is extracted, transformed, and loaded (ETL) into a central repository.</td></tr><tr><td><strong>Integration Style</strong></td><td>Dynamic integration at query time for real-time access.</td><td>Pre-processed and integrated data stored in the warehouse.</td></tr><tr><td><strong>Latency</strong></td><td>Higher latency due to live querying of distributed sources.</td><td>Lower latency for queries because of pre-aggregated data.</td></tr><tr><td><strong>Flexibility</strong></td><td>Highly flexible; new data sources can be added with minimal effort.</td><td>Less flexible; changes in data sources may require re-engineering ETL processes.</td></tr><tr><td><strong>Use Cases</strong></td><td>Ideal for real-time access and integration of distributed systems.</td><td>Suited for historical data analysis, reporting, and batch processing.</td></tr></tbody></table></div><div><strong><br></strong></div><h3><strong>Analogy:</strong></h3><ul><li><strong>Data Federation</strong> is like having live access to books in multiple libraries through a single search tool, without physically borrowing or copying them.</li><li><strong>Data Warehousing</strong> is like creating a single, well-organized library by copying and categorizing books from multiple sources.</li></ul></Back>
